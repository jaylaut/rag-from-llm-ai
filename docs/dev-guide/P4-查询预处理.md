# P4 · 查询预处理开发指引

## 一、本阶段要做什么

一句话：**用户问问题的方式五花八门，这个阶段在"检索之前"，先把问题"翻译、改写、拆解"成更容易被搜中的形式。**

这是 RAG 从"能用"走向"好用"的关键一步，也是**简历含金量最高的一环**（因为很多教程只做到 P3 就停了）。

💡 类比：用户问"我买的那个东西咋退款啊？"——直接拿这句话去搜，可能搜不到"售后政策"文档。P4 做的事，就是把这句话先"翻译"成"商品退款流程"，再去搜，命中率大增。

```
用户原始问题 → ① 改写/扩展 → ② 路由分类 → ③ 再去做检索（P2）
```

---

## 二、涉及的技术逐个拆解

### 2.1 查询改写（Query Rewriting / HyDE）

**它是什么**：让大模型先把用户的问题"润色"或"翻译"成更适合检索的形式。

**两种常见做法**：

1. **Query Rewrite（直接改写）**：把口语化问题改成规范表述
   - 例："咋退款" → "如何申请商品退款流程"
2. **HyDE（Hypothetical Document Embeddings，假设性文档嵌入）** 🎓：
   - 思路很巧妙：先让模型**凭空编一段"假想的答案"**，拿这段"假答案"去检索
   - 原理 💡：答案和真实文档的用词、风格更接近，比问题本身更容易"撞上"库里的文档
   - 例：问"怎么退款"→ 模型编"申请退款需要进入订单页、点击申请退款、填写原因、等待审核…"→ 拿这段去搜，能搜到真实文档里"点击申请退款"那句
   - 这个原理很经典，建议单独学习（搜"HyDE 假设文档嵌入 RAG"）

### 2.2 查询扩展（Query Expansion）

**它是什么**：给问题"加料"，扩充出多个相关说法，多路检索取并集。

**常见做法**：
- **同义扩展**：退款 → 退货、退费、refund
- **多查询**：一个问题拆成好几个角度，各搜一次，结果合并
- **🎓 进阶**：Multi-Query（多查询生成）——让模型把一个模糊问题拆成 3 个具体子问题分别检索
- **🎓 Step-Back Prompting（回退提示）**：让模型先抽象出问题背后的"高层概念"，用更宽泛的问法去检索。例：问"氢氧化钙在 25℃ 的溶解度"→ 回退成"氢氧化钙的化学性质"→ 用后者检索到更广的上下文。适合"问得特别具体、原文可能没有逐字对应"的场景

### 2.3 查询路由（Query Routing）

**它是什么**：先判断"这是哪一类问题"，然后**分流到不同的处理方式**。

**为什么需要** 💡：不是所有问题都该走同一条路：
- "这个 API 怎么用？" → 走代码文档检索
- "最近的新闻是什么？" → 可能要走联网搜索，而不是查本地库
- "帮我算 123×456" → 根本不用检索，直接算

**本项目的简化实现**：先用规则或小模型判断问题类型，再决定"走向量检索 / 走 BM25 / 直接回答"。

> 🎓 路由是"模块化 RAG 编排层"的核心算子之一，本阶段先做简单版，完整版在 P5 编排层展开。

## 三、动手步骤 📋

1. 先做最实用的一个：**HyDE 或 Query Rewrite**（二选一先跑通）
   - 写一个函数，调 QWEN-MAX 把原始问题改写成检索友好形式
2. 再做 **Multi-Query**：让模型把问题拆成 2~3 个子问题，各自检索，合并去重
3. 最后做**简单路由**：按关键词/规则分类（如"含'算'字 → 直接答"），分流
4. 每加一个，都对比"加了之后，检索命中率有没有提升"（见下）

## 四、怎么验证做对了 ✅

这是 P4 最重要的部分——**量化证明这些优化真的有效**（也是简历上要填的 X%）：

1. 准备一组"口语化、模糊、表述不规范"的问题（比如 20 个）
2. 对比三组：**不预处理 vs 加改写 vs 加改写+扩展**
3. 分别统计检索命中率（找到正确文档的比例）
4. 预期结果：加了预处理后，命中率明显提升 → 这就是你简历里"查询预处理使检索命中率提升 X%"的数字来源

## 五、常见坑 ⚠️

1. **改写后反而跑偏**：模型改写可能"过度脑补"，把原意带歪。要保留原始问题做兜底（原问题也搜一次，合并结果）
2. **HyDE 编得太离谱**：假想答案如果方向错了，会带偏检索。可以把 HyDE 结果和原问题各搜一次，融合
3. **每次查询都调大模型，慢 + 费钱**：预处理调一次模型、检索、生成又调一次，链条变长。要权衡"值不值得"——对复杂问题才预处理，简单问题直接搜
4. **路由规则太死板**：纯关键词规则容易误判。可先用规则，后续换小模型做分类
