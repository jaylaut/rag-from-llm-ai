# P3 · 生成开发指引

## 一、本阶段要做什么

一句话：**把 P2 检索到的几段文字，加上用户的问题，一起喂给大模型，让它生成一个"有依据、不瞎编"的回答。**

到这里，RAG 的最小闭环就打通了：**检索 → 生成**，系统第一次能真正"回答问题"。

```
检索到的几段文字 + 用户问题 → 拼成一段提示词 → 发给 QWEN-MAX → 拿到回答
```

---

## 二、涉及的技术逐个拆解

### 2.1 大语言模型（LLM）

**它是什么**：就是 ChatGPT、通义千问这类"会聊天、会写文章"的 AI。它本质是个"超级接话机"——你给它一段文字，它预测"下一句最该说什么"。

**我们用的**：`qwen-max`（通义千问的旗舰模型），通过阿里云百炼平台远程调用。

**为什么用远程 API，而不是本地跑** 💡：
- 大模型很"重"，好的模型要几十 GB 甚至上百 GB 显存
- 你的显卡只有 4GB，本地只能跑"迷你版"模型，效果差一截
- 所以用**远程 API**：模型在阿里云的服务器上跑，我们通过网络把问题发过去、收回答

**为什么选 qwen-max**：
1. 中文能力强（国产模型，中文是强项）
2. 走 **OpenAI 兼容接口**——以后想换别的模型，改一个名字就行，代码不用动
3. 支持 **Function Calling**（工具调用）——这是 P7 做 Agent 的硬前提，现在选的模型要能撑到那一步

---

### 2.2 RAG 的核心原理：为什么要"检索 + 生成"而不是直接问模型

这是整个项目的灵魂，务必理解 💡：

**大模型有两个天生毛病**：
1. **会瞎编（幻觉）**：你不知道的事它会一本正经地编。比如问它"我公司上季度业绩"，它不知道也能编一堆。
2. **知识是旧的**：模型训练完就"定格"了，训练之后发生的新事它不知道。

**RAG 就是治这两个毛病的药**：
- 先从你自己的资料库里**检索**出相关事实
- 再把这些事实**塞进提示词**，告诉模型"别瞎编，就照着这些资料回答"
- 模型就从"凭记忆瞎说"变成"对着资料照本宣科"

💡 类比：考试时，直接问一个学生"答这题"（可能瞎蒙）；RAG 相当于"先给他一本开卷资料，让他翻着资料答"——答案就靠谱多了。

---

### 2.3 提示词工程（Prompt Engineering）

**它是什么**：怎么把"问题 + 资料"组织成一段话发给模型，让它的回答最靠谱。

**本项目的提示词结构**（三段式）：

```
【系统提示】你是一个严谨的助手，只依据资料回答，不要编造…
【参考资料】[1] 来源：xxx  内容：…
            [2] 来源：xxx  内容：…
【用户问题】…
【回答】
```

**关键设计点（都是治幻觉的手段）**：

1. **明确"只依据资料，不要编造"**：直接约束模型
2. **要求"资料不足就说找不到"**：防止它硬编
3. **标注引用来源**：让回答可溯源，你能验证它说的对不对
4. **控制 temperature（温度）**：设低一点（0.3），让回答更"老实"，少发挥

**一个容易被忽略的细节（lost-in-the-middle）** 💡：

大模型对长上下文有个"中间丢失"效应——对开头和结尾的内容记得牢，对**中间**的内容容易忽略。所以组装参考资料时，**别把最相关的块按顺序堆中间**，而是：

- 最相关的 1~2 块放**最前**（模型最先看到、印象最深）
- 次相关的放**中间**
- 也很相关的 1 块放**最后**（收尾印象）

这样最关键的证据"一头一尾"，模型不容易漏。

**temperature 是什么** 💡：一个控制模型"脑洞大小"的旋钮。0 是"死板、只选最可能的词"，1 是"天马行空"。回答事实性问题要设低，写诗写小说要设高。

---

### 2.4 引用溯源（Citation）

**它是什么**：让回答里标注"这句话出自哪份资料"。

**为什么是亮点**：这是 RAG 可信度的核心。面试官会问"你的系统怎么保证不瞎编？"——答案就是"每一句都有据可查，来源清清楚楚"。

**实现思路**：在提示词里给每段资料编号 `[1][2][3]`，要求模型回答时引用编号。回答末尾汇总"引用了哪些资料"。

---

## 三、动手步骤 📋

1. 去阿里云百炼平台申请 `DASHSCOPE_API_KEY`，填进 `.env`
2. 写 `generator.py`：用 `requests` 直接调 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`
3. 写提示词模板（系统提示 + 资料编号 + 引用要求）
4. 把 P2 的检索结果 + 问题，拼进模板，发请求，拿到回答
5. 串起来：P2 检索 + P3 生成 = 完整问答

---

## 四、怎么验证做对了 ✅

1. 问一个"资料里明确有答案"的问题 → 回答正确，且引用了正确来源
2. 问一个"资料里没有"的问题 → 回答会说"资料中未找到"，而不是瞎编
3. 问一个"容易诱导幻觉"的问题 → 看它是否坚持依据资料
4. 检查引用的来源编号，和实际检索到的资料对得上

---

## 五、常见坑 ⚠️

1. **API Key 写死在代码里**：务必放 `.env`，不要提交到 git（会泄露，还能被薅羊毛）
2. **温度设太高**：回答开始"发挥"，脱离资料瞎编。事实问答设 0.3 左右
3. **资料塞太多超长**：一次塞几十段，可能超模型上下文限制，或让模型抓不住重点。控制 top-3~5 段即可
4. **不要求引用**：模型回答看似合理，但无法验证真假。一定要求标注来源
5. **🎓 进阶可学**：流式输出（Streaming，像 ChatGPT 那样一个字一个字往外蹦，体验好很多）——放 P6 做 API 时一起实现
